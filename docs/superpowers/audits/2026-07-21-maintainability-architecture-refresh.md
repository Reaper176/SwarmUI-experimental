## Current Architecture

### Repository and composition baseline

SwarmUI has three principal maintained runtime layers: a classic-script/Razor browser frontend under `src/Pages`, `src/wwwroot/js`, and `src/wwwroot/css`; the C# application and Web/API host under `src`; and Python execution supplied chiefly by excluded upstream Comfy code, with Swarm-owned nodes confined to `src/BuiltinExtensions/ComfyUIBackend/ExtraNodes` (`AGENTS.md`, `src/Core/Program.cs`, and `src/BuiltinExtensions/ComfyUIBackend/ExtraNodes`). Built-in extensions under `src/BuiltinExtensions` connect these layers without changing the executable composition root.

`Program.Main` is the process composition and lifecycle root (`src/Core/Program.cs`). After settings and extension discovery, it calls extension `OnPreInit`, builds model lists and default parameter registrations, constructs `BackendHandler`, `SessionHandler`, and `WebServer`, calls `Web.PreInit`, runs extension `OnInit`, loads models and backends, registers APIs through `BasicAPIFeatures.Register`, prepares the Web host, runs extension `OnPreLaunch`, and launches it. `Program.Shutdown` invokes `PreShutdownEvent`, cancels `GlobalProgramCancel`, stops the Web host, backends, sessions, proxy, and model handlers, then calls extension `OnShutdown` and shuts down output metadata tracking. Process-wide owners remain publicly reachable through `Program.Backends`, `Sessions`, `T2IModelSets`, `Extensions`, `ServerSettings`, `Web`, and `GlobalProgramCancel`.

The direct-qualified maintained-C# consumer inventory, bounded to `src/**/*.cs` while excluding external extensions, downloaded nodes, and build output, found: `Program.Backends` 61 references in 18 files; `Sessions` 58 in 8; `T2IModelSets` 45 in 16; `Extensions` 13 in 3; `ServerSettings` 168 in 42; `Web` 5 in 4; and `GlobalProgramCancel` 90 in 25. These counts identify the breadth of the existing composition surface; they do not characterize those references as defective.

`WebServer` owns ASP.NET/Razor composition and request routing (`src/Core/WebServer.cs`). `WebServer.Prep` configures middleware, response compression, static files, WebSockets, Razor Pages, shutdown integration, the `/API/{*Call}` dispatcher, output/view routes, extension files, and audio. `API.APIHandlers` is the route registry; `API.RegisterAPICall` adds either an `APICall` or a reflected delegate; and `API.HandleAsyncRequest` owns HTTP/WebSocket parsing, session resolution, permission enforcement, reflective dispatch, and response/error transport (`src/WebAPI/API.cs` and `src/WebAPI/APICallReflectBuilder.cs`). `BasicAPIFeatures.Register` registers account/session/general routes and composes `T2IAPI`, `ModelsAPI`, `BackendAPI`, `AdminAPI`, `UtilAPI`, and `PromptLabAPI` (`src/WebAPI/BasicAPIFeatures.cs`). Static registration searches found 147 `API.RegisterAPICall` sites across 11 maintained C# files, including built-in Comfy, Grid Generator, and Image Batch Tool contributions.

The current T2I route owner is already split by capability: `T2IAPI.Register` preserves the route-composition surface while registering methods owned by `ImageHistoryAPI`, `KritaAPI`, and `ClassicInpaintAPI` alongside generation and parameter/model-refresh methods (`src/WebAPI/T2IAPI.cs`, `src/WebAPI/ImageHistoryAPI.cs`, `src/WebAPI/KritaAPI.cs`, and `src/WebAPI/ClassicInpaintAPI.cs`). On the browser side, `ImageHistoryController` remains in `outputhistory.js` and composes `ImageHistoryFilter`, `ImageHistoryComparison`, and `ImageHistoryBulkActions` from their separate files; the Image Editing coordinator is owned by `src/wwwroot/js/genpage/helpers/image_editor_ui.js`. These are current committed boundaries, not assumptions carried forward from the 2026-07-20 audit.

`ExtensionsManager` discovers built-in extension types from loaded assemblies and external extension projects from `src/Extensions`, instantiates `Extension` subclasses, and orders their lifecycle calls (`src/Core/ExtensionsManager.cs`). The `Extension` base contributes `ScriptFiles`, `StyleSheetFiles`, `OtherAssets`, metadata, and `OnFirstInit`/`OnPreInit`/`OnInit`/`OnPreLaunch`/`OnShutdown` hooks (`src/Core/Extension.cs`). Extensions also contribute through shared registries such as `API.RegisterAPICall`, `T2IParamTypes.Register`, `BackendHandler.RegisterBackendType`, permissions, and `WorkflowGenerator` step lists. `WebServer.GatherExtensionPageAdditions` converts extension script/style/asset lists and `Tabs/Text2Image/*.html` files into served resources and generated page fragments. Thus `Program` owns lifecycle order, `ExtensionsManager` owns discovery/instances, each `Extension` owns its contribution declarations, and `WebServer` materializes browser-facing contributions.

Backend ownership is centered on `BackendHandler`: `AllBackends` is a concurrent configured-instance registry, `BackendTypes` is the type catalog, `Load` and `Shutdown` own configured lifecycle, and `GetNextT2IBackend` plus request/pressure registries coordinate T2I acquisition and model-loading pressure (`src/Backends/BackendHandler.cs`). `SessionHandler` owns concurrent session, user, and role registries plus persistent login sessions (`src/Accounts/SessionHandler.cs`). Each `T2IModelHandler` owns a concurrent model catalog and refresh/shutdown behavior, while `Program.T2IModelSets` maps model categories to those handlers (`src/Text2Image/T2IModelHandler.cs` and `src/Core/Program.cs`). The broad collection declaration search found 308 static or instance `Dictionary`, `ConcurrentDictionary`, `HashSet`, `List`, or array declarations across maintained C#; this is an inventory of registry/state locations only.

The Comfy built-in is the adapter boundary between C# generation and Python nodes. `ComfyUIBackendExtension` registers assets, parameters, backend types, lifecycle work, and feature discovery; `ComfyCapabilityCatalog` maps detected node classes to feature identifiers; `ComfyNodeNames` and `ComfyNodeInputNames` centralize maintained class/input strings used by the backend APIs, `WorkflowGenerator`, `WorkflowGeneratorSteps`, `WorkflowGeneratorModelSupport`, and `WGNodeData` (`src/BuiltinExtensions/ComfyUIBackend`). `WorkflowGenerator` and its ordered step lists build Comfy JSON graphs. Swarm-owned Python modules publish their runtime node mappings and schemas under `ExtraNodes`; downloaded Comfy and node repositories remain outside maintained scope.

The read-only launcher surface has distinct platform paths. `launch-linux.sh` and `launch-macos.sh` source `launchtools/linux-build-logic.sh`, which repairs the .NET path, optionally pulls, rebuilds when commit markers demand it, retains a failed-build backup, and sets host environment before the launcher starts the built server; exit code 42 re-enters the launcher. `launch-windows.bat` carries equivalent pull/build/backup/start/restart logic, while `launch-linux-dev.sh` and `launch-windows-dev.ps1` force debug rebuild paths. `launchtools/install-linux.sh` and `install-windows.bat` install prerequisites, clone SwarmUI, and hand off to the platform launcher. Docker launch scripts build the selected Dockerfile, mount the applicable repository/data/backend paths, and call inner scripts that return to `launch-linux.sh`. Separately, runtime installation and updates are owned by `Installation.Install` and Admin API routes such as `CheckForUpdates`, `UpdateAndRestart`, extension update/install methods, and `InstallDotnetUpdate` (`src/Core/Installation.cs` and `src/WebAPI/AdminAPI.cs`).
